Support

If you're stuck or have found a bug, start with the answers below, then the user guide. If that doesn't settle it, open an issue and the maintainer will take a look.

Only the latest release gets fixes, so please update before you report a problem.

Get in touch

  • Bugs and feature requests: open an issue at github.com/AesonFord/Renami/issues. Search first; someone may have reported it already.
  • Security problems: don't open a public issue. Use the private report form described in the security policy. You'll hear back within 7 days.
  • Privacy: the privacy policy explains what Renami stores and the one request it makes.

What to put in a bug report

  1. Your Renami version. On macOS, Renami menu, then About Renami. On Windows, Settings, Apps, Installed apps. On Linux, flatpak info app.renami, snap list, or dpkg -s renami. A copy downloaded from this site also tells you under Check for Updates….
  2. Your operating system and version, and whether you installed Renami from this site, from an app store, or built it yourself.
  3. What you did and what happened: the pattern you used, the options you set, a few example file names before and after, and what you expected instead.
  4. The log file, if Renami showed an error or crashed. It is called renami.log and lives in ~/Library/Application Support/Renami on macOS, %APPDATA%\Renami on Windows, and ~/.config/Renami on Linux. It holds error messages and times, which can include file paths, so read it over before you attach it.

Common questions

Nothing was renamed, and Renami says files changed since the preview

Renami checks every file again just before renaming. If one has been renamed, moved, or edited since the preview was made, perhaps by another program or a sync service, it stops and renames nothing, so the names you checked are the names you get. The preview is refreshed; look it over and click Rename again.

Rename is greyed out

The status under the preview says why: the pattern has an error, Renami is still reading file details, or some files have errors. A file with an error, such as a name that would collide with an existing file or a token with no value and no fallback, blocks the whole batch. Fix the pattern, or untick those files to leave them out, and Rename comes back.

Can I undo after quitting?

Not from the app. Undo Last Rename works until you quit, and Renami warns you before quitting while an undo is still available. For renames you want to be able to reverse later, use the command line with --journal, which writes an undo file you can replay any time. Before a large rename, Export Preview gives you a CSV of every old and new name, which is a good record to keep.

Some names got a number added, or a token came out empty

When two files would end up with the same name, Renami adds a suffix to the later one and flags the row. When a token has no value for a file, say {camera_model} on a screenshot, the token renders as nothing, and the row is flagged too. Tick Show only files that need a look above the preview to see just those rows. A fallback, written {camera_model|unknown}, fills the gap; adding {seq} keeps names apart.

Reading file details is slow

Photo, video and audio details come from ExifTool, which reads each file. Large video files and network or external drives take longest. Checksums ({crc32}, {md5}) read every byte of every file, so use them only when you need them. You can keep editing the pattern while Renami reads; the preview fills in as it goes.

macOS asks whether Renami may access my Desktop, Documents or Downloads

That is macOS protecting those folders. Renami needs the permission to rename files there, and asks only when you add files from such a place. If you declined and want to change your mind, open System Settings, Privacy & Security, Files and Folders, and switch Renami's access back on.

The created date didn't change on Linux

Linux file systems don't let programs set a file's creation date, so the Set created date to date taken option is disabled there. The modified date works on every system.

A HEIC or RAW photo shows no preview

For a camera RAW file, Renami shows the preview image the camera stored inside it, so a RAW file without one shows no picture. HEIC files are decoded in full. In both cases the file's details and new name are unaffected.

I downloaded Renami from this site and my system won't open it

The downloads on this site are not signed with an Apple or Microsoft certificate, so the system asks before the first launch. The first launch notes on the download page explain the one-time step for macOS and Windows. If you installed Renami from an app store, it is signed and this step doesn't apply.

The AppImage won't start on Ubuntu

Ubuntu 24.04 and later restrict unprivileged user namespaces, which the AppImage needs. Install the .deb instead, or allow the AppImage with an AppArmor profile.

How do I turn off the update check?

Clear Check for Updates Automatically: it's in the Renami menu on macOS and the Help menu on Windows and Linux. Renami then never contacts the network unless you choose Check for Updates… yourself. If you installed Renami from an app store, that store handles updates.

Where do my presets live, and can I move them to another computer?

In presets.json in the application data folder listed above. Copy that file to the same place on the other computer. A preset holds a pattern and its options, never the files.

Can I rename from a script?

Yes. The renami command line uses the same engine as the app, previews by default, and needs --apply to change anything. The README documents it, including settings files, JSON output and exit codes.

Checking a download

Every release on GitHub comes with a SHA256SUMS file and a build attestation that proves the installer was built by the project's own release workflow. The security policy shows the two commands to check them.
